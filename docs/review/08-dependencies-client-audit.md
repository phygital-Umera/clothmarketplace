# Dependencies and client-side security audit

Scope: `backend/`, `frontend/` (admin), `user/` (storefront), `frontend/my-three-app`. No source edited, no install run in the repo. Format: title | file:line or package | issue | fix. Items marked "unverified" were not confirmed.

## Method and caveats

- `npm audit --package-lock-only --json` was run online (advisory database current at run time) in a scratch copy of each `package.json` and lockfile.
- `backend/` has **no `package-lock.json`** (only `frontend/` and `user/` do). I generated a throwaway lockfile with `npm install --package-lock-only --ignore-scripts` in the scratch dir, so the backend results reflect whatever versions the ranges resolve to today, not what production runs. Finding D1 covers this.
- Totals. frontend: 34 vulnerable packages (2 critical, 20 high, 11 moderate, 1 low). user: 32 (2 critical, 20 high, 9 moderate, 1 low). backend: 13 (0 critical, 5 high, 8 moderate).
- Most frontend findings are build-time or dev-server tooling that never ships to browsers (vite, rollup, esbuild, postcss, babel, glob, minimatch, picomatch, brace-expansion, cross-spawn, js-yaml, yaml, ajv, browserslist, nanoid, source-map-js, flatted, lint-staged, tanstack router-plugin/generator). They matter for developer machines and CI only. These are grouped in D7.

## Checked and OK

- No `dangerouslySetInnerHTML`, `eval`, `new Function`, `postMessage`, `insertAdjacentHTML` or `document.write` outside H1 and legacy Event code (grep of both apps).
- `QrCodeGenerate.tsx:42,89` `innerHTML` assigns static button text only.
- No secrets in `VITE_*` variables: `frontend/.env.example` holds only `VITE_SERVER_URL`; `user` reads only `VITE_SERVER_URL`. `.env` files are git-ignored; `git ls-files` shows only `.env.example` files. Razorpay `keyId` comes from the API (public key, expected). The only other `import.meta.env` use is `VITE_EXTERNAL_VENDOR_BASE_URL` in legacy `components/Event/RawMaterialOrder.tsx:78` (undefined in the example env).
- No cookies are used by either SPA (`document.cookie`, `withCredentials`, `credentials` absent), so classic CSRF does not apply to them today. It becomes relevant if H2's fix moves tokens to cookies, or if the backend's `accessToken` cookie path in `verifyJWT` (backend review M1) is combined with a permissive CORS.
- No tokens, passwords or JWTs logged in the auth code paths (`frontend/src/utils/axios.ts`, `context/AuthContextProvider.tsx`, `pages/Signin.tsx`, `user/src/lib/api.ts`, `auth.tsx`).
- Open redirects: storefront `redirect` param is validated through `safeRedirect` for `signin` and `signup`; all producers pass in-app paths (`checkout.tsx:14`, `ProductCard.tsx:21`, `product.$id.tsx:139`). The admin app has no redirect query param (landing path comes from the role).
- No source maps produced by the Vite configs (default off) and no `dist/` or `.map` files tracked.
- Third-party scripts: only Razorpay (dynamic, route-scoped) and Google Fonts stylesheet; no analytics or tag managers in either `index.html`.
- No `postMessage` listeners; no `window.open` with user-controlled URLs (only the print window in H1, which is `about:blank`).
- `href`/`src` from data: `mailto:${company.email}` (`CompanyDetailsDrawer.tsx:72`) and the WhatsApp `r.link` (`BranchCustomerDuesPage.tsx:366`, backend-built) are not JavaScript-URL capable by construction (unverified for `r.link`'s source on the backend).
- Razorpay payment signature verification and amount computation are server-side (backend review).
- Backend `express` 5.3.0, `jsonwebtoken` 9.0.3, `@prisma/client` 5.22.0, `bcryptjs` 2.4.3, `helmet` 7, `express-rate-limit` 7: no audit findings for these in this run. (`jsonwebtoken` 9.x is the patched line; Prisma 5 is a major behind current but not flagged.)
- `frontend` and `user` run React 18.3 with no audit findings on `react`, `react-dom`, `@tanstack/react-query`, `react-hook-form`, `jwt-decode`.
