# Frontend (admin) and storefront review

Scope: `frontend/src` (excluding legacy catering folders) and `user/src`. Read-only static review by grep and reading. Nothing was run. Format: title | file:line | problem | fix. Items marked "unverified" were not confirmed.

## High

1. **mustChangePassword never enforced** | `frontend/src/pages/Signin.tsx:33-39`, `frontend/src/hooks/useCurrentUser.ts:15`, `frontend/src/lib/api/Auth/auth.ts:42`, `frontend/src/layouts/AppLayout.tsx` | The flag is typed and returned by login and `/users/me`, but nothing reads it (grep finds only the two type declarations). Staff with a temporary password can use the whole panel. | In AppLayout, if `me.mustChangePassword` and the path is not `/change-password`, redirect there. Also enforce on the backend.
2. **Access and refresh tokens in localStorage in both apps** | `frontend/src/context/AuthContextProvider.tsx:39`, `frontend/src/utils/axios.ts:14-15,33`, `user/src/lib/api.ts:15-22` | Any XSS can steal the long-lived refresh token. No `dangerouslySetInnerHTML` exists in live code, which limits today's risk, but third-party scripts load (Razorpay, Google Fonts). | Move the refresh token to an httpOnly SameSite cookie, or at least add a strict CSP. Whether the backend rotates refresh tokens is unverified.
3. **Unguarded JSON.parse and jwtDecode in request interceptors** | `frontend/src/utils/axios.ts:14-15,42`; `user/src/lib/api.ts:44` | `readToken()` has no try/catch and `jwtDecode` throws on a malformed token. Every API call then fails with a cryptic error and the user is never signed out. | Wrap in try/catch and end the session on failure.
4. **Admin refresh is clock-based only, no retry after 401, hard reload on logout** | `frontend/src/utils/axios.ts:17-22,43-54,72-74` | The token is refreshed only after the client clock says it expired (the storefront refreshes 10 s early). A skewed clock sends an expired token. A 401 triggers `window.location.assign('/signin')` with no refresh-and-replay, which discards an in-progress POS bill. | Add a 401 interceptor that refreshes once and replays the request. Navigate with the router, not a full reload.
5. **POS bill save has no re-entry guard, and the client sends prices** | `frontend/src/pages/shop/pos/NewBillPOSPage.tsx:456-526` (buttons disabled at 1331, 1348) | `handleCompleteBill` never checks `save.isPending`. Only the buttons are disabled, so a fast double trigger before re-render can create two CONFIRMED bills (stock deducted twice). The payload sends `unitPrice: l.rate`, `discount` and `taxRate` from the client (lines 511-518). Whether the backend revalidates against the variant price is unverified. | Return early on `save.isPending`. Send an idempotency key per bill. Confirm the server recomputes price and tax.
6. **No automated tests in either app** | `frontend/`, `user/` | `find` for `*.test.*` returns nothing. Per my grep of `package.json`, no vitest or jest script is present. POS maths (`NewBillPOSPage.tsx:292`) and checkout are untested. | Add vitest. Start with totals maths and the payment flow.

## Medium

7. **Storefront checkout: no idempotency, order exists before payment** | `user/src/routes/payment.tsx:118-146` | `busy` state blocks most double clicks, but no idempotency key is sent, so a timeout then retry can create duplicate orders. `reset()` clears the checkout choice as soon as the order is created. The coupon code comes from client state. If the tab closes during the Razorpay modal, the order stays unpaid; recovery exists via `/payment?ref=` and My Orders (good). | Send an idempotency key. Confirm the server recomputes totals and coupon.
8. **Razorpay `payment.failed` rejects early and can mark a later success as failed** | `user/src/routes/payment.tsx:55-75` | `payment.failed` sets `settled = true` and rejects, but Razorpay lets the user retry inside the same modal. If they then succeed, the page has already navigated to retry and called `paymentApi.failed`. Whether the backend handles this safely is unverified. | Reject only on dismiss; rely on server verification or a webhook.
9. **Dismissed modal recorded as a failure** | `user/src/routes/payment.tsx:135,224` | `paymentApi.failed` is called for a plain close, not just a bank decline. | Distinguish dismiss from failure.
10. **Stale cart total at payment** | `user/src/routes/payment.tsx:105-127` | The cart is cached (30 s per docs). The button total can differ from what the server charges, and the UI does not warn. | Refetch on entering `/payment` and show the server total before opening Razorpay.
11. **Admin route guard is client-side only** | `frontend/src/layouts/AppLayout.tsx:35-80`, `frontend/src/hooks/usePermissions.ts:12-15` | Acceptable only if every endpoint enforces permissions (see backend review). `can()` returns true when no permission is passed. Whether a new route missing from `canOpen` is denied by default is unverified. | Keep `canOpen` deny-by-default and add a test.
12. **Hard-coded fallback URLs and an import-time crash** | `frontend/src/utils/axios.ts:7,11` (`http://localhost:5692/api/v1`), `components/QrCode/QrCodeGenerate.tsx:23` (`localhost:5173`), `components/Loader/Loader.tsx:7` (lottie.host), `components/Vendor/ShareLink.tsx:22` (`menubook.cc`, legacy). `user/src/lib/api.ts:10` calls `.replace` on an unset env var and crashes at import. | A prod build with a missing env silently calls localhost (admin) or white-screens (storefront). | Fail fast with a clear message; remove legacy URLs.
13. **Giant components** | `frontend/src/pages/shop/pos/NewBillPOSPage.tsx` (1580 lines), `components/Bills/BillFormModal.tsx` (953), `pages/promotions/PromotionsPage.tsx` (894), `pages/shop/barcode/BarcodeLabelsPage.tsx` (865), `pages/shop/stock/StockPage.tsx` (796), `pages/shop/customers/CustomerPage.tsx` (796); storefront `user/src/routes/product.$id.tsx` (480) | Hard to test and re-renders heavily. POS reset (`NewBillPOSPage.tsx:535-548`) is 14 hand-written setters. | Split into hooks and sub-components; one `resetBill()`.
14. **POS hotkeys and tablet use** | `NewBillPOSPage.tsx:174-198` | F1/F4/F6/F8 do nothing on touch. The effect re-subscribes on every field change with a hand-listed dependency array that may leave `handleHoldBill` stale (unverified). Tablet layout was not tested. | Use a ref to the latest handler; test at 768 px.
15. **No code-splitting in the storefront** | `user/vite.config.ts:6,13` | `TanStackRouterVite()` is used without `autoCodeSplitting`, and `chunkSizeWarningLimit: 1500` hides the warning. The admin uses `.lazy.tsx` routes (good). | Enable `autoCodeSplitting`, lower the limit.
16. **Storefront SEO and image performance** | `user/index.html`, `user/src/components/ui.tsx:33` | Client-rendered SPA with one static title and description, so no per-product title, Open Graph or JSON-LD. `loading="lazy"` is missing on `components/account.tsx:159`, `AuthShell.tsx:20`, `routes/account/returns.tsx:140`, `reviews.tsx:116`. No width/height or srcset, so layout shift. Google Fonts stylesheet is render-blocking. | Per-route title and meta, image dimensions, consider prerendering.
17. **Silent truncation of lists** | `frontend/src/pages/shop/customers/CustomerPage.tsx:78` (`limit: 50`), `NewBillPOSPage.tsx:82` (employees `limit: 50`), `:163` (product search `limit: 30`) | I found no pager at these call sites (not exhaustively checked). Rows beyond the limit are invisible. The storefront product list is paginated (`products.tsx:72`, good). | Add pagination or server-side search.
18. **Over-broad query invalidation** | `user/src/lib/queries.ts:198-200` | `useCheckout` invalidates every private query plus all products. Admin mutations were not exhaustively audited (unverified). | Invalidate only cart, orders and affected products.
19. **TypeScript looseness** | both apps | About 221 `any` (`: any`, `as any`, `<any>`) by grep, including some remaining legacy folders, so live code is lower. 9 ts-ignore or eslint-disable. `strict: true` is on, but `noUnusedLocals` and `noUnusedParameters` are false in `frontend/tsconfig.app.json:22-23` and `user/tsconfig.app.json:22-23`, which hides dead code. The admin axios interceptor returns `res.data` while typed `AxiosInstance`, so callers cast (`lib/api/Auth/auth.ts:55,61`). | Type the wrapper; enable the unused flags after deleting legacy code.

Icon-only buttons in admin were not audited (unverified). | Use native radios; add `rel`.

25. **No cross-tab logout** | both apps | No `storage` event listener, so signing out in one tab leaves others active. | Add a listener.

Verified fine: event listeners in Calendar, POS, Layout have cleanup; admin layout checks the token role against `/users/me`; storefront RequireAuth guards private routes; refresh is single-flight in both apps; Razorpay signature verification is server-side; a retry-payment recovery route exists.
